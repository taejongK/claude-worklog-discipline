## 자동 문서화 규칙 (필수)

작업과 함께 문서를 갱신한다. 아래 상황에서는 **사용자가 요청하지 않아도 자동으로** 실행한다.
레포 최상위는 역할별로 나눈다:

```
README.md     프로젝트 소개 (사람이 읽는 첫 문서)
docs/         문서 — 진입점은 docs/index.md
src/          코드 (권장. 기존 레포의 코드 위치는 옮기지 않는다)
```

문서를 찾거나 새로 만들 때는 `docs/index.md` 에서 시작한다.

### 커밋 시 (docs/worklog 날짜별 로그) — 항상

```
0. 언제 기록하는가
   - 기록한다: 커밋하기 직전. worklog 변경을 그 커밋에 함께 포함한다.
   - 기록한다: 사용자가 "기록해줘"/"정리해줘"라고 요청한 시점 (커밋 여부·파일 변경 여부와 무관).
     이때 그날 로그의 항목 순서·중복도 함께 정리한다.
   - 기록하지 않는다: 커밋 없이 끝난 작업(요청이 없으면), worklog만 고친 커밋, "기록 생략" 지시.
   - 같은 날 같은 질문에 대한 후속 커밋은 새 항목을 만들지 않고 기존 `###` 항목을 갱신한다.

1. 기록할 때는 docs/worklog/{YYYY_MM_DD}.md (오늘 날짜) 에 기록한다.
   - 파일이 없으면 `## {YYYY_MM_DD}` 헤더로 새로 만든다.
   - 작업 단위는 `### {작업 제목}` 으로 파일 끝에 append 한다.

2. 작업 항목 하나는 질문 하나에 대한 답이다.
   항목을 그대로 복사해 보고에 붙여 쓸 수 있어야 한다. 독자는 코드를 보지 않은 사람이다.
   아래 순서로 쓴다:
   - 질문: 이 작업을 왜 했는가. 누가 물었든 스스로 물었든, 작업이 답하려 한 질문을 한 줄로.
   - 결과 요약: 질문에 대한 간결한 답. 확인 못 했거나 실패했으면 그 사실이 답이다.
   - 방법: 어떻게 작업·실험해서 그 답을 얻었는가. 가장 중요한 부분이다.
     - 결과를 믿을 수 있는 근거를 여기에 둔다: 조건(데이터·환경·버전), 비교 대상, 수치, 확인 방법.
     - 코드 수준이 아니라 일의 흐름으로 쓴다.
   - 남은 문제: 답의 한계, 미검증 부분 (없으면 생략)
   - 작업자: 이름 (모르면 사용자에게 물어본다)

3. 코드 변경점을 나열하지 않는다 (그건 git 이 기록한다).
   파일·함수명은 독자가 위치를 찾는 데 꼭 필요할 때만 최소한으로 쓴다.

4. 헤더는 `##`(날짜)와 `###`(작업)만 쓴다.
   항목 내부 구분은 별도 헤더 대신 위의 `라벨:` 불렛으로 가볍게 표현한다.

5. 줄글로 쓰지 않는다. 라벨 아래는 하위 불렛으로 구조화하고 짧게 쓴다.
   - 불렛 하나는 한 줄, 한 가지 사실. 문장 대신 명사형·개조식으로 끝낸다.
   - 수식어·경위 설명·반복을 뺀다. 빼도 뜻이 통하면 뺀다.
   - 볼드체(**...**)를 쓰지 않는다.
   예:
     ### 로그인 세션 만료 버그 수정
     - 질문: 사용자가 30분 만에 강제 로그아웃되는 원인은? 막을 수 있나?
     - 결과 요약: 토큰 갱신 요청 누락이 원인. 만료 5분 전 자동 갱신으로 해결
     - 방법:
       - 갱신 시점 로그 추적 → 만료 직전 갱신 요청 0건 확인
       - 만료 5분 전 자동 갱신 추가
       - 2시간 연속 사용 테스트 3회 → 로그아웃 0회 (수정 전 3회 모두 30분에 로그아웃)
     - 남은 문제: 다중 탭 동시 갱신 미검증
     - 작업자: 홍길동
```

### 문서를 만들거나 옮길 때 (docs/index.md)

```
docs/index.md 는 docs/ 아래 문서의 목차다. 코드(src)는 다루지 않는다 (AGENTS.md 가 맡는다).
- docs/ 아래 문서를 새로 만들거나, 옮기거나, 지우면 같은 작업 안에서 index.md 를 갱신한다.
- 폴더별 `##` 섹션 아래 문서마다 한 줄: - [{제목}]({상대경로}) — {한 줄 요약}
- worklog 는 날짜 파일을 하나하나 나열하지 않고 폴더 링크만 둔다.
```

### 디렉터리 구조 변경 시 (AGENTS.md 계층)

```
새 디렉터리 추가/역할 변경 시 해당 디렉터리의 AGENTS.md 를 갱신한다.
- 상위 디렉터리 AGENTS.md 의 Subdirectories 표도 함께 갱신.
- <!-- MANUAL: --> 마커 아래 손으로 쓴 내용은 절대 덮어쓰지 않는다.
- 없으면 Purpose / Key Files / Subdirectories / For AI Agents 섹션과
  끝의 <!-- MANUAL: --> 마커로 새로 만든다.
```
